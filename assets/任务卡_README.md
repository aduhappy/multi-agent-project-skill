# 任务卡目录索引

> 新 agent 进来不知道先做哪张卡？看这里。本文件列依赖链与当前状态；**卡面规矩、通用铁律与各角色须知统一见 `文档/协作规矩.md`**（唯一出处）。
> 单张任务卡细节看对应的 `.md` 文件；全量看板看 AGENTS.md §4。
> 🔴 一个任务一张卡：执行和独立复核在同一张卡里，复核**不单列一行**。

## 依赖链（谁依赖谁，可并行哪些）

```
T1 → T2 → T4
        ↘
T3 ─────→ T5 → T6（T3 与 T2 可并行）
```

> 用 ASCII 画依赖图，箭头表示"完成后才能开始"。可并行的分支并排画。

## 任务卡清单（每卡一行，任务名 ≤30 字；细节在卡里，不在这里复述）

| 编号 | 任务名 | 状态 | 依赖 | 文件 |
|---|---|---|---|---|
| Tx | 【例：数据清洗（建真实卡后替换示例行）】 | ⬜可派 | 无 | `任务卡/Tx_示例.md` |
| Ty | 【例：模型拟合】 | 🟠待裁定（不可派） | Tx | `任务卡/Ty_示例.md` |
| Tz | 【例：已收口归档样】 | ✅已收口（D-xx） | 无 | `任务卡/Tz_示例.md` |

**当前可派**（YYYY-MM-DD）：【列出 ⬜ 的卡和建议执行/复核模型；等用户的事另列】

> **新 agent 找活干**：状态列找第一个 ⬜，检查它的依赖是否都 ✅，再打开卡确认“进度回写”仍是 ⬜，是→开干。
> **命名约定**：任务卡文件名 `T<编号>_<简短主题>.md`，如 `T1_数据清洗.md`。

## 例行签核提示词（合入权威文档后用；卡里只写参数，不另加提示词）

````text
请作为【卡号】合入签核方，核对主控合入【权威文档路径】的【新增段，例：§十二】。你与写这段的 agent 同家族就停下告诉我。
先读：AGENTS.md，任务卡【路径】的“进度回写”和“主控收口”，复核报告【路径】，草案【路径】。
只读。要查：1）合入前的部分是否没动（主控给的前缀字节数与 SHA-256：【值】）；2）新增段与草案、复核后的订正是否一致，每个数能否在产物表里用脚本核到；3）措辞有没有越过卡面 🔒 措辞。
报告写到【文档/<卡号>_合入签核_<模型名>_<日期>.md】，开头写身份，意见分“## 会出错”（写出错场景）和“## 建议”（无则写“无”），末尾单独一行只写 PASS 或 NEEDS_FIX。在 STATUS.md 末尾追加交接段（四节，≤800 字），不改其他文件。
做完用几句大白话告诉我：能不能引用、有没有对不上的地方。
````

## 例行阶段通读提示词（可选：一版成品完成时做一次，不是每张卡必做）
由用户或主控直接贴给一个新窗口，不必开卡。通读方不读历史，建议可能踩已否决的路、重提已做过的事：建议一律回主控，对照决策表和历史筛过再采纳，不直接当待办。
````text
请作为【成品名】的通读方，当审稿人读【成品路径】。成品只读，只新建指定报告；不给你卡和项目历史，只读这一份。
报告写到【路径】，开头写身份（工具／模型／家族／日期），负面结果放最前。依次报：结构撑不撑得起论点、逻辑断点、缺口、审稿人最可能问的 5 个问题；每条建议注明“未核对项目历史”。
做完用几句大白话告诉我：最大的三个问题。
````

## 当前推荐入口

- **如果从零接手**：从第一个 ⬜ 的任务开始，往前读它的依赖任务的卡。
- **如果接上一个 agent 的棒**：先读 STATUS.md（增量 handoff），再读 AGENTS.md §3（累计快照），最后定位到当前任务的卡。
