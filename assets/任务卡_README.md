# 任务卡目录索引

> 新 agent 进来不知道先做哪张卡？看这里。本文件列依赖链、当前状态，并且是**卡面规矩的唯一出处**。
> 单张任务卡细节看对应的 `.md` 文件；全量看板看 AGENTS.md §4。
> 🔴 一个任务一张卡：执行和独立复核在同一张卡里，复核**不单列一行**。

## 卡面规矩（主控出卡、改卡时照做）

**谁改卡面哪里**

| 位置 | 执行方 | 复核方 | 主控 |
|:--|:--|:--|:--|
| 卡面“进度回写” | 自己那一行；⬜→⏳（开工）、⏳→🟡（交回） | 自己那一行；🟡→🔵（交回报告） | 主控行；✅ / ⛔ / 🗄️ / 🟠 |
| 卡面其余各节 | 不改；停与不停见下“停止条件” | 不改 | 就地改，记变更记录 |
| `STATUS.md` 交接段 | 追加（四节 ≤800 字） | 追加（四节 ≤800 字） | 追加（四节 ≤800 字） |
| `AGENTS.md` 任何一节，本索引 | 不改 | 不改 | §3、§3.5、§4 与本索引在派发、收口时同步；对不上以卡面为准（检查器 A007、A008 提示） |

没有主控的单 agent 项目，由该 agent 兼任主控那一列。主控不替用户派执行方、复核方（含子代理），用户点名除外。

**分阶段交回（样张/中间稿）**：先交样张或部分成果请主控/用户过目时，卡面状态保留 `⏳执行中`，在“进度回写”执行方行注明“样张待主控看”（并追加 `STATUS.md` 交接段），**不改 `🟡待复核`**——避免复核方把 `🟡` 当正式完工信号误审样张；全部成果齐备后再改 `🟡待复核`。

**自由度**（建卡时在“范围”行选一个）
- `写死`：计算、口径、判据类。🔒 节写死原句、阈值、措辞。
- `目标＋底线`：写作、结构、图面类。只列目标、底线和“建议”（写在“注意”节），不给参考原句；执行方可调整结构，新分析写进“建议”、不执行。底线至少含：数字只取权威层已有的数（需新派生数回主控另开计算卡）；已登记的否决决定不得重新提出为待做事项（可在“建议”里注明分歧）。
- 措辞纪律写成“禁止的说法 → 可用的说法”对照，前提与限定集中交代一处，不要求逐句带限定。

**计数和派生数一律脚本给出**：页数、条数、图数、均值、合计、占比等计数与派生数都由脚本算出，留存命令与输出；禁止心算或手数（主控自己出卡、收口时的计数同样用脚本）。写作卡只引用权威层已有的数，要新数回主控开计算卡。

**闸门查交付物本身**：落盘后必须重新打开**最终交付文件本身**（如 `.docx`、`.pptx`、`.xlsx`、`.csv`、`.tif`），用脚本核对页数/行列数、关键文字、图片数、字体或汇总统计；只看导出预览图（PNG/PDF）和运行日志不算过闸门。

**停止条件分两类**：实质的（数对不上、红线冲突、要改定义）停下报告；程序性的（来源格式、文件名、旧字样等，不改数也不改结论）记进“偏离”继续，交回时列出，主控事后裁定。

**主控小改**：单句或格式级、不改数、不改结论、改前改后可回溯的，主控可直接改并在变更记录留一行；其余仍派执行方。

**复核与返工**：
- 默认先冷读——只读成品，不读卡面“主控在立项前看过什么”“🔒”节、执行方结果说明和“一句话结果”，把读不通、对不上、缺口记成报告第一节并存档，再对照卡面与执行方结果（复制即用的开头段在模板复核方提示词里）。
- **核查类卡不替复核方划范围**：卡面写“全部 X”（如全部图件、全部表格），不在目标或提示词里写“目前只有某几处”；主控对范围的初步判断只能写在“主控在立项前看过什么”（冷读阶段不读）。复核方第一步用脚本自己列出全量清单，再与卡面对照，差异单列。
- **复核意见分两节**：负面结果放最前，正文意见固定分 `## 会出错`（每条必须写清“出错场景：在什么输入或状态下，得到什么错误结果”）与 `## 建议`（写不出具体出错场景的疑虑、写法偏好放此节；某节无内容写“无”）。报告末尾**单独一行**只写 `PASS` 或 `NEEDS_FIX`（“会出错”有条目即为 `NEEDS_FIX`，检查器 A012 提示）。
- **只按“会出错”返工**，“建议”不触发返工；多方分歧并列给证据，不投票；同一产物审—改最多 3 轮，仍有分歧交用户。

**主控收口三查**：标 `✅已收口` 前必做三项——① 通读执行方交接/说明的“没做什么（含范围外发现）”与复核报告的“会出错”节；② 用脚本重开最终交付物核一遍页数、图数、关键文字或统计（同“闸门查交付物本身”）；③ 同步 `AGENTS.md`（TL;DR、§3、§3.5、§4）与本索引，跑 `check_handoff.py`。

**决策表只登记约束后续工作的决定**；流程微调记卡面变更记录。

**别让卡越写越大**

1. 🔒 节（定义、判据、阈值、措辞红线）写死：只许补澄清（标日期、决策 ID，不改值）；要改值就登记新决策、开新卡。
2. 其余各节（输入指纹、产物、注意、提示词）由主控**就地改成最新**；每改一次在卡末“变更记录”记一行（日期｜决策 ID｜改了哪节｜为什么）。不在卡末追加“主控补充”“以本节为准”——那样新 agent 得自己把五六节拼成现状。答执行方的问题，把答案写回对应的节。共性环境坑记入 `文档/环境坑.md`，卡面只放链接，不复述。
3. 同时有效的派发提示词只留**执行、复核两段**（同一任务多路并派时每路一段）。返修就把这两段就地改成返修版；用过的提示词在收口时删掉，变更记录留一行。
4. 下面几种情况**开新卡**，新卡开头写“接 Tx”，旧卡进度回写写“由 Ty 接续”：
   - 要改 🔒 节的值；
   - 原做法作废、要换做法重跑；
   - 收口后想再加一项计算或分析；
   - 下一步是另一类活（合入权威文档、改正文、出图）；
   - 多步串行、每步换人且中间要主控裁定（卡号加 a、b）。
5. 收口时瘦身：主控行一两句结论，细节进 STATUS 和决策记录；删用过的提示词。
   只差措辞时可以不退回（可选）：数值经独立复算复现、只改措辞或解读、不改判读档位，主控可在执行方结果说明末尾追加“主控收口附注”（注明交回版 SHA、以附注为准）；改了数或判读档位就照常 ⛔ 退回。
6. 体积线：卡 ≤15KB、提示词段 ≤3（标题带 📋 或“提示词”的都算一段，A006 超限时列出最大三节；提示词标题一律以 📋 开头；已收口 ✅ 与作废 🗄️ 卡不查 A005 提示词完整性）；本索引 ≤15KB、`STATUS.md` ≤40KB、`AGENTS.md` ≤25KB（A003：`STATUS` 与 `AGENTS` §3 超限跑 `python scripts/archive_status.py`，`AGENTS` §3.5 决策表超限按规矩迁全文至 `文档/决策记录/决策登记表_全文.md`）；“进度回写”每行 ≤400 字（A009）；`AGENTS.md` §3 每条 ≤600 字（A010）；`STATUS.md` 最新交接段 ≤800 字且四节齐（A011）。超了先看是不是该拆卡、细节该不该进 STATUS 或归档。

## 例行签核提示词（合入权威文档后用；卡里只写参数，不另加提示词）

````text
请作为【卡号】合入签核方，核对主控合入【权威文档路径】的【新增段，例：§十二】。你与写这段的 agent 同家族就停下告诉我。
先读：AGENTS.md，任务卡【路径】的“进度回写”和“主控收口”，复核报告【路径】，草案【路径】。
只读。要查：1）合入前的部分是否没动（主控给的前缀字节数与 SHA-256：【值】）；2）新增段与草案、复核后的订正是否一致，每个数能否在产物表里用脚本核到；3）措辞有没有越过卡面 🔒 措辞。
报告写到【文档/<卡号>_合入签核_<模型名>_<日期>.md】，开头写身份，意见分“## 会出错”（写出错场景）和“## 建议”（无则写“无”），末尾单独一行只写 PASS 或 NEEDS_FIX。在 STATUS.md 末尾追加交接段（四节，≤800 字），不改其他文件。
做完用几句大白话告诉我：能不能引用、有没有对不上的地方。
````

## 例行阶段通读提示词（可选：一版成品完成时做一次，不是每张卡必做）
由用户或主控直接贴给一个新窗口，不必开卡。通读方不读历史，建议可能踩已否决的路、重提已做过的事：建议一律回主控，对照决策表和历史筛过再采纳，不直接当待办。
````text
请作为【成品名】的通读方，当审稿人读【成品路径】。成品只读，只新建指定报告；不给你卡和项目历史，只读这一份。
报告写到【路径】，开头写身份（工具／模型／家族／日期），负面结果放最前。依次报：结构撑不撑得起论点、逻辑断点、缺口、审稿人最可能问的 5 个问题；每条建议注明“未核对项目历史”。
做完用几句大白话告诉我：最大的三个问题。
````

## 当前推荐入口

- **如果从零接手**：从第一个 ⬜ 的任务开始，往前读它的依赖任务的卡。
- **如果接上一个 agent 的棒**：先读 STATUS.md（增量 handoff），再读 AGENTS.md §3（累计快照），最后定位到当前任务的卡。
