# 迁移协议（整棵树换位置时用）

> 由 `AGENTS.md` §5「开跑先自证身份」引出。**平时不用读，要迁移时读。**

## 一、为什么身份判据只能用绝对路径

| 候选标识 | 为什么不行 |
|:--|:--|
| **HEAD sha** | clone 之间**相同** → 放行错误的树；又随正常提交**变化** → 拒绝正确的树 |
| **HEAD 黑名单**（「HEAD 不得等于 X」）| 两棵树停在同一 commit 时（刚 clone/复制完最常见）把**正确的树**一起拦掉 |
| **remote / 分支 / 有没有 `AGENTS.md`** | 旧 clone 全都一样，「是不是一个有效仓」≠「是不是**本任务指定**的那棵树」 |
| ✅ **仓库根完整绝对路径** | 机器上唯一 |

📌 **已知代价**：合法迁移时路径会变，判据会在**正确的树**上失败。
这是**权衡不是解决**（迁移罕见、clone 混淆常见）——代价由下面的迁移三步兜住。

## 二、迁移后必须做三件事

**缺一，下一个 agent 就会被正确的判据拦在正确的树外面。**

### ① 更新在途任务卡的路径判据

- **谁做**：执行迁移的那个 agent（**不是下一个**）
- **怎么找全**：任务卡索引里状态为「待派发 / 进行中 / 待复核」的**全部**卡，逐张改
- **完成证据**：🔴 **不是「全树命中为 0」**——历史报告、归档、只读副本、第三方依赖里
  留有旧路径是**正常且无害**的，全树永远归不了零（实测某项目残留数千处命中）。
  **判据限定在「活动执行面」**，而这个面必须是**算出来的闭集**、不是**圈出来的目录**：
  - **入口** = 编排器 / 构建脚本里**实际被调用**的文件（从源码机器提取，**不手写清单**）
  - **面** = 从入口沿 `import` 与 `subprocess` **递归展开的传递闭包**
  - **该面内命中为 0**；报告给出闭包怎么算的（入口从哪来、展开到第几层、用什么解析）
  - 🔴 **不许用目录名圈定**——目录既会漏（打包产物里的脚本副本、动态 import）
    也会多（同目录下的废弃文件）
  - 📌 **面外命中不必逐条证明「无害」**（那是散文不是判据）——
    **「不在面内」本身就是判据**，面外只列清单备查

  🔴 **落地前必须先定死这三件，否则两个人算出两个数**：

  | 要定的 | 建议 |
  |:--|:--|
  | 闭集里的「文件」指什么 | 源码与被读取的配置；排除产物、缓存、第三方依赖、打包副本 |
  | `subprocess` 展开到哪层 | 静态字面量**必须**展开；变量拼接/配置传入**静态不可判定**，这类调用要在项目里**显式登记**清单，别假装闭包能自动覆盖 |
  | 用什么解析 | 有解析器用 AST；**没有时如实标注「文本扫描」，不许用正则冒充 AST 闭包** |

- 🔴 **别忘了仓库之外**：agent / 工具的配置里也会写死项目路径
  （可写根、trusted 项目列表、IDE 工作区、定时任务）。
  **不更新这些，下一个 agent 会在正确的树里被自己的工具拦住。**

### ② 在新位置重跑验收确认恢复

- **跑哪一套**：迁移前那一次的**同一套门、同一编排入口、同一解释器**（版本写进报告）
- **判据**：🔴 **只比 rc 不够**——退出码相同而产物错了的情况真实存在。
  除逐门 rc 一致外，还要对照**关键产物的哈希**与**各门的汇总行**
- 🔴 **「关键产物」不许人工挑**——取 **manifest 里登记的那一组**。
  **通常需要两份**：**发布 manifest**（交付物 + 哈希）与
  **回归 manifest**（每门 → 它的产物路径 + 哈希）。缺哪份先建哪份
- 🔴 **汇总行要能机器提取，前提是格式统一**——实测同一项目里并存
  `N/M`、`PASS/FAIL`、`ALL_ZERO`、自然语言等多种写法。
  **先约定一条汇总行契约**（字段与格式）再用；
  🔴 **没有契约就不要把「汇总行对照」当判据**——否则门会因格式而非事实失败
- **证据**：新旧两份 summary + 关键产物指纹一并留档

### ③ 旧树留一份指向新位置的标记

🔴 **用途是【导航与审计】，不是拦截**：给**人**看的线索、事后追溯的凭据。
**不要指望它挡住 agent**（见 `经验教训.md`）。**拦截只靠 ① 的路径判据。**
