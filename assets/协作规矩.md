# 协作规矩（multi-agent-project 通用规范，唯一出处）

> 本文件由 `multi-agent-project` 技能整份提供，升级时可直接整份替换；**项目不直接修改本文件**（检查器 A016 校验首行版本与正文哈希）。
> 项目特有的口径、路径或对本文件某条规矩的例外，统一写在 `AGENTS.md` §5“本项目例外”小节。本文件中“权威层”统一指 `文档/关键数字.md` 和 `AGENTS.md` §3.5 决策登记表。

## 一、谁改哪里

**谁改卡面哪里**

| 位置 | 执行方 | 复核方 | 主控 |
|:--|:--|:--|:--|
| 卡面“进度回写” | 自己那一行；⬜→⏳（开工）、⏳→🟡（交回） | 自己那一行；🟡→🔵（交回报告） | 主控行；✅ / ⛔ / 🗄️ / 🟠 |
| 卡面其余各节 | 不改；停与不停见下“停止条件” | 不改 | 就地改，记变更记录 |
| `STATUS.md` 交接段 | 追加（四节 ≤800 字） | 追加（四节 ≤800 字） | 追加（四节 ≤800 字） |
| `AGENTS.md` 任何一节，任务卡索引（`文档/任务卡_README.md`） | 不改 | 不改 | §3、§3.5、§4 与任务卡索引在派发、收口时同步；对不上以卡面为准（检查器 A007、A008 提示） |

没有主控的单 agent 项目，由该 agent 兼任主控那一列。主控不替用户派执行方、复核方（含子代理），用户点名除外。“进度回写”里的**状态行顶格写**（如 `- 状态：⬜可派`，不缩进、不放进代码块或注释；检查器只认顶格状态行）。

状态：🟠待裁定（不可派）/ ⬜可派 / ⏳执行中 / 🟡待复核 / 🔵待收口 / ✅已收口 / ⛔退回 / 🗄️作废。**只有 ⬜ 可派**（状态行顶格写）。家族按模型名写（GPT→OpenAI、Claude→Anthropic、GLM→智谱、DeepSeek→DeepSeek 等），连模型名都不知道才写 UNKNOWN；不从工具名猜。UNKNOWN 不算通过。每张卡**自包含**：零上下文 agent 读本卡 + 线级 `AGENTS.md`/`STATUS.md` + `文档/协作规矩.md` + 卡内列出的输入即可开工，不依赖聊天记录。一个任务一张卡，执行和独立复核同卡。

**分阶段交回（样张/中间稿）**：先交样张或部分成果请主控/用户过目时，卡面状态保留 `⏳执行中`，在“进度回写”执行方行注明“样张待主控看”（并追加 `STATUS.md` 交接段），**不改 `🟡待复核`**——避免复核方把 `🟡` 当正式完工信号误审样张；全部成果齐备后再改 `🟡待复核`。

## 二、卡面规矩

**自由度**（建卡时在“范围”行选一个）
- `写死`：计算、口径、判据类。🔒 节写死原句、阈值、措辞。
- `目标＋底线`：写作、结构、图面类。只列目标、底线和“建议”（写在“注意”节），不给参考原句；执行方可调整结构，新分析写进“建议”、不执行。底线至少含：数字只取权威层已有的数（需新派生数回主控另开计算卡）；已登记的否决决定不得重新提出为待做事项（可在“建议”里注明分歧）。（“权威层”统一指 `文档/关键数字.md` 和 `AGENTS.md` §3.5 决策登记表。）
- 措辞纪律写成“禁止的说法 → 可用的说法”对照，前提与限定集中交代一处，不要求逐句带限定。

**计数和派生数一律脚本给出**：页数、条数、图数、均值、合计、占比等计数与派生数都由脚本算出，留存命令与输出；禁止心算或手数（主控自己出卡、收口时的计数同样用脚本）。写作卡只引用权威层已有的数，要新数回主控开计算卡。

**闸门查交付物本身**：落盘后必须重新打开**最终交付文件本身**（如 `.docx`、`.pptx`、`.xlsx`、`.csv`、`.tif`），用脚本核对页数/行列数、关键文字、图片数、字体或汇总统计；只看导出预览图（PNG/PDF）和运行日志不算过闸门。

**停止条件分两类**：实质的（数对不上、红线冲突、要改定义）停下报告；程序性的（来源格式、文件名、旧字样等，不改数也不改结论）记进“偏离”继续，交回时列出，主控事后裁定。

**复核与返工**：
- 默认先冷读——只读成品，不读卡面“主控在立项前看过什么”“🔒”节、执行方结果说明和“一句话结果”，把读不通、对不上、缺口记成报告第一节并存档，再对照卡面与执行方结果（具体步骤见下文“五、复核方须知”）。
- **核查类卡不替复核方划范围**：卡面写“全部 X”（如全部图件、全部表格），不在目标或提示词里写“目前只有某几处”；主控对范围的初步判断只能写在“主控在立项前看过什么”（冷读阶段不读）。复核方第一步用脚本自己列出全量清单，再与卡面对照，差异单列。**任务卡文件名不得含“复核”**（核查类卡命名请用“核查/核对”，否则检查器 A015 会按放错目录的复核报告拦截）。
- **复核意见分两节**：负面结果放最前，正文意见固定分 `## 会出错`（每条必须写清“出错场景：在什么输入或状态下，得到什么错误结果”）与 `## 建议`（写不出具体出错场景的疑虑、写法偏好放此节；某节无内容写“无”）。报告末尾**单独一行**只写 `PASS` 或 `NEEDS_FIX`（“会出错”有条目即为 `NEEDS_FIX`，检查器 A012 提示）。
- **只按“会出错”返工**，“建议”不触发返工；多方分歧并列给证据，不投票；同一产物审—改最多 3 轮，仍有分歧交用户。

**决策表只登记约束后续工作的决定**；流程微调记卡面变更记录。

**别让卡越写越大**

1. 🔒 节（定义、判据、阈值、措辞红线）写死：只许补澄清（标日期、决策 ID，不改值）；要改值就登记新决策、开新卡。
2. 其余各节（输入指纹、产物、注意、提示词）由主控**就地改成最新**；每改一次在卡末“变更记录”记一行（日期｜决策 ID｜改了哪节｜为什么）。不在卡末追加“主控补充”“以本节为准”——那样新 agent 得自己把五六节拼成现状。答执行方的问题，把答案写回对应的节。共性环境坑记入 `文档/环境坑.md`，卡面只放链接，不复述。
3. 同时有效的派发提示词只留**执行、复核两段**（同一任务多路并派时每路一段）。返修就把这两段就地改成返修版；用过的提示词在收口时删掉，变更记录留一行。
4. 下面几种情况**开新卡**，新卡开头写“接 Tx”，旧卡进度回写写“由 Ty 接续”：
   - 要改 🔒 节的值；
   - 原做法作废、要换做法重跑；
   - 收口后想再加一项计算或分析；
   - 下一步是另一类活（合入权威文档、改正文、出图）；
   - 多步串行、每步换人且中间要主控裁定（卡号加 a、b）。
5. 收口时瘦身：主控行一两句结论，细节进 STATUS 和决策记录；删用过的提示词。
   只差措辞时可以不退回（可选）：数值经独立复算复现、只改措辞或解读、不改判读档位，主控可在执行方结果说明末尾追加“主控收口附注”（注明交回版 SHA、以附注为准）；改了数或判读档位就照常 ⛔ 退回。
6. 体积线：卡 ≤15KB、提示词段 ≤3（标题带 📋 或“提示词”的都算一段，A006 超限时列出最大三节；提示词标题一律以 📋 开头；已收口 ✅ 与作废 🗄️ 卡不查 A005 提示词完整性）；任务卡索引（`文档/任务卡_README.md`）≤15KB、`STATUS.md` ≤40KB、`AGENTS.md` ≤25KB（A003：`STATUS` 与 `AGENTS` §3 超限跑 `python scripts/archive_status.py`，`AGENTS` §3.5 决策表超限按规矩迁全文至 `文档/决策记录/决策登记表_全文.md`）；“进度回写”每行 ≤400 字（A009）；`AGENTS.md` §3 每条 ≤600 字（A010）；`STATUS.md` 最近 5 段交接 ≤800 字且四节齐（A011）。超了先看是不是该拆卡、细节该不该进 STATUS 或归档。

## 三、通用铁律

- **代码归位**：脚本进 `scripts/`，不散落根目录。每新增一个脚本，同步更新 `scripts/README.md`（写清这个脚本干嘛、输入、输出、谁写的）。根目录只放入口文件和薄指针。
- **收工规矩**：谁改哪里、复核两节式与收口三查只看本文件（`文档/协作规矩.md`）；`STATUS.md` 只追加**增量 handoff**（四节：改了什么 / 怎么验证的 / 没做什么 / 不确定处，≤800 字，不重复 §3），体积超限时跑 `python scripts/archive_status.py` 归档旧段。🔴 主控登记推翻或暂停某个结论的决策时，同一次收工由主控在入口 TL;DR 和故事段挂红旗，不能只登记决策行。收工时从本线目录运行 `python ../scripts/check_handoff.py --scope line`；若脚本复制在线目录则运行 `python scripts/check_handoff.py --scope line`（执行方、复核方可用 `--role executor|reviewer --card T<卡号>`）。根索引另用 `--scope index`。
- **独立复核分级阀门**：产物类型决定复核深度--
  - 纯文本/格式类（写作、格式转换）：自检够；成品完成后可选一次阶段通读（见 `文档/任务卡_README.md`）。
  - **分析建模/参数选定**（模型拟合、调优、样本集清洗）：**必须独立复核**--另一 agent 或主控抽验关键数字（守恒/边界/格数/量级/各文档一致性），通过才算完成。
  - **论文结论/头条数字**（端点均值、百分比变化、方向判定）：**必须跨模型家族独立复核**。
  - "自检全过"不构成通过判据，闸门须用脚本重开最终交付物本身核对（只看日志或导出图不算）。独立复核通过前，产物标记为"待验，下游不得启用"。不确定时走完整流程。
  - 🔴 **复核方的结论同样要可证伪**：复核方用单一来源下的断言、凭记忆写的数字、未实测的推测，**不因为出自复核方就更可信**。
  - 🔴 **执行方有权停下来质疑任务卡，质疑本身不计为失败**——出卡方也会错，没有哪一方不可质疑。主控/出卡方写进卡面的数字、抽查结论同样要注明出处，计数与派生数一律由脚本给出。
- 🔴 **开跑先自证身份**（🟡 仅多树 / 迁移 / 克隆项目保留本条，其他项目删掉）：**第一条动作**跑并贴出
  `git rev-parse --show-toplevel`，与任务卡写明的**仓库根完整绝对路径**比对，不一致**立刻停下报告**。
  🔴 **标识只能是绝对路径**——不许用 HEAD sha，也不许用 HEAD 黑名单。
  📌 为什么、以及迁移后要做什么 → `文档/迁移协议.md`
- 🔴 **关键测量双源交叉**：会推翻结论、触发删除/迁移、或决定验收数的**测量**，
  必须用**两种失效模式不同**的方法各测一次；任务卡写明：被测量量定义、两个来源、容差、验收阈值。
  🔴 **两源不一致 → 记 `UNKNOWN`、停下游、禁止投票、禁止静默挑一个。**
  🔴 **两源容差内一致却分别落在验收阈值两侧 → 同样记 `UNKNOWN` 并停**（「测量一致」≠「结论一致」）。
  📌 为什么不用多数表决 → `文档/经验教训.md`
- **关键数字单一来源**：同一数字（均值/百分比/面积/统计量等）只在权威层（`文档/关键数字.md` 和 `AGENTS.md` §3.5 决策登记表；累计快照见 STATUS.md 或 AGENTS.md §3）一处写定，别处引用不复述；计数与派生数一律由脚本算出。收工前核对所有文档间数字一致性——同一数字在不同文档差 1% 以上即视为 bug，必须对齐才能交。
- **坏产物退役隔离**：发现某 agent 产物错了，立即做四件事：① 目录/文件名加 `_DEPRECATED` 后缀或移入 `_作废/` 子目录；② 在 §5（铁律节）顶部用红字 `> ⚠️ 【作废】<路径> <原因>` 标注（别标在 §3——§3 是累计快照，坏产物标记应和铁律/规范同在 §5）；③ 更新 §4 看板状态为 `[x]` + 标注"作废"；④ 更新 STATUS.md 反映作废。绝不只靠记忆说"那个别用"。

## 四、执行方须知

卡面标 🔒 的定义、判据、阈值都已写死，不得改动。先读：`AGENTS.md`（入口，尤其 §3.5、§5、§7），本节（执行方须知），再读任务卡全文，照卡做。

1. 开工第一件事：看卡面“进度回写”的状态，不是 ⬜可派 就停下告诉我；是就改成 ⏳执行中，填执行方那一行的工具、模型、模型家族、开工日期。然后按卡面核对输入，实质对不上就停，程序性出入记进“偏离”继续（见上文“二、卡面规矩”之“停止条件分两类”）。哈希只记判据依赖的对象（声称未改的输入、交付物），开工、收尾各算一次比对；不给每份日志逐个记。
2. 先过卡面闸门（落盘后必须用脚本重开最终交付文件本身核对页数/行列数、关键文字、图片数或字体，只看导出图和日志不算），不过就停，告诉我差在哪。
3. 细读卡末提示词列出的本卡最容易做错的条目与“注意”节（共性环境与软件坑见 `文档/环境坑.md`）。
4. 结果照实报，不利的、不成立的都报；措辞守卡面“措辞”。计数和派生数一律由脚本算出并贴命令与结果；写作类卡只取权威层已有的数，需要新数停下回主控开计算卡。
5. 产物落点照卡面“产物”。不能动：卡面与提示词列出的只读路径、原始数据、已有运行目录、口径或正文；若要改权威文档，只写草案，不直接改。
6. 交回前（中途停下也一样）：在“进度回写”填交回日期、产物路径、一句话结果、偏离或疑点（没有写“无”），做完了把状态改成 🟡待复核，停下了状态留 ⏳、在疑点里写清停在哪；再在 STATUS.md 末尾追加交接段（“谁做的”一行＋固定四节：改了什么 / 怎么验证的（命令与结果原文）/ 没做什么（含范围外发现）/ 不确定处，整段 ≤800 字）。只改这两处，别的由主控改（见上文“一、谁改哪里”）；收工跑 `python scripts/check_handoff.py --role executor --card T<卡号>` 自检；实质有错或做不下去就先停下告诉我。做完先确认“进度回写”已改，再用几句大白话回答卡末提示词的问题。

## 五、复核方须知

先读：`AGENTS.md`（尤其 §3.5、§5）；本节（复核方须知）；任务卡的卡头与“进度回写”；冷读之后再读卡面其余各节和执行方的结果说明与产物。

开工第一件事：看卡面“进度回写”，状态不是 🟡待复核 就停下告诉我；只看执行方那一行的家族（不读其“一句话结果”），本卡属论文结论/头条数字类而你与执行方同家族，也停下告诉我。没问题就填复核方那一行的工具、模型、模型家族、日期。

先冷读：只读成品，不读卡面“主控在立项前看过什么”“🔒”节、执行方结果说明和“一句话结果”；若是核查类任务，第一步先用脚本自己列出全量对象清单；把读不通、对不上、缺口记成报告第一节并存档，再读卡面与执行方结果逐项对照（清单范围有差异的单列）。只读，不改执行方的任何文件，不复用执行方的脚本，计数与数值自己写代码重算。对照时要查：
1. 输入核对：执行方有没有按卡面核对，开工、收尾指纹是否一致。
2. 闸门自己重做：用脚本重开最终交付文件本身核对页数/行列数、关键文字、图片数、字体，不只看导出图。
3. 关键数与派生数换一条路径独立重算（按卡面指定或换用不同的来源或方法）；对不上又说不清原因的记 UNKNOWN。
4. 执行方有没有改卡面 🔒 节，或者事后加了说法。
5. 结果说明里的每个数能不能在输出表或脚本结果里找到；措辞有没有越线。

报告写到 `文档/T<编号>_独立复核_<模型名>_<日期>.md`（或卡面指定路径，勿放进 `文档/任务卡/`），开头写身份（工具／模型／模型家族／日期），负面结果放最前，正文意见分两节：
- `## 会出错`：每条写问题，再写“出错场景：在什么输入或状态下，得到什么错误结果”。
- `## 建议`：写不出出错场景的疑虑、写法偏好放这里。
哪一节没有内容就写“无”。末尾单独一行只写 PASS 或 NEEDS_FIX（“会出错”有条目就写 NEEDS_FIX）。交回前在“进度回写”复核方那一行填结论（PASS／NEEDS_FIX／UNKNOWN）和报告路径，状态改成 🔵待收口（不论结论）；再在 STATUS.md 末尾追加交接段（四节，≤800 字）。只改这两处，别的由主控改（见上文“一、谁改哪里”）；收工跑 `python scripts/check_handoff.py --role reviewer --card T<卡号>` 自检。做完先确认“进度回写”已改，再用几句大白话告诉我：能不能过（PASS 还是 NEEDS_FIX）、有没有对不上的数、执行方有没有动 🔒 节。

## 六、主控须知

**主控小改**：单句或格式级、不改数、不改结论、改前改后可回溯的，主控可直接改并在变更记录留一行；其余仍派执行方。

**主控收口三查**：标 `✅已收口` 前必做三项——① 通读执行方交接/说明的“没做什么（含范围外发现）”与复核报告的“会出错”节；② 用脚本重开最终交付物核一遍页数、图数、关键文字或统计（同“闸门查交付物本身”）；③ 同步 `AGENTS.md`（TL;DR、§3、§3.5、§4）与任务卡索引（有看板标记时跑 `python scripts/sync_board.py`），跑 `check_handoff.py`。

**建卡与签核自查**：
- 卡面每个数字都注明出处（脚本/文件 + 口径）；没核过的标“主控估算”。执行方开工先核对，对不上就停。
- 模拟／检验类卡派出前主控自查三项：① 效应方向与预期一致——把“参数＞0 时会怎样”的句子和式子符号对一遍；② 随机种子不跨格重叠（例：格序号×1000＋第几次，不用“格序号＋第几次”）；③ 闸门里有“复现已有结果”一条。
- 执行方交回 → 用户派独立复核（与执行方不同 agent；分析建模、头条数字类已收口卡复核方家族不能为空，论文结论/头条数字类须不同模型家族，复核方自己重算；主控只按复核报告“会出错”节触发返工）→ 主控执行“收口三查”、登记决策。复核通过前产物标“待验”，下游不得启用。合入权威文档签核用 `文档/任务卡_README.md` 的例行签核提示词，不在卡里加新提示词。

**脚本解析格式边界**（避免手写变形触发漏识别）：
- `STATUS.md` 交接段标题仅认带空格的 `## ` 或 `### `（无空格 `##Handoff` 不算交接段；仅任务卡 `##进度回写` 特例兼容无空格旧卡），段内小节标题勿含 `Handoff` 或 `交接` 字样（否则会被拆成新交接段），日期用半角数字（全角数字日期不取数）。
- 任务卡“进度回写”状态行只认顶格无序列表或裸行且须含状态图标（有序列表 `1. 状态：`、表格内状态行、纯文字无图标如 `状态：进行中` 均不识别）；任务卡文件名统一用大写前缀 `T<编号>_<主题>.md`，且**任务卡文件名不得含“复核”**（含“复核”会被 A015 当成放错目录的复核报告拦截，核查类卡请用“核查/核对”）；决策表 ID 统一用半角短横线 `D-01`（勿用连接号 `D–01`）。
