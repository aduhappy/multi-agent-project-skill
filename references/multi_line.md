# 并列多线课题（软件 / 论文 / 专利 这类）

一个课题下有几条并列的线——各自独立推进、又共享一套口径。根与线是**不同 scope**，不要塞进一个 `AGENTS.md`，也不要各写各的互不相干。

🔴 **关键前提：agent 的工作目录通常直接设在某一条线**（如 `.../01_软件`），不是课题根。所以线级必须自包含，根不能在关键路径上。

```
<课题根>/
├── AGENTS.md          ← 根索引（从 assets/ROOT_AGENTS.md 复制）：线目录 · 跨线阶段 · 共享权威指针 · 跨线阻塞
├── STATUS.md          ← 只记跨线增量
├── 01_软件/  AGENTS.md · STATUS.md · 薄指针 · 自己的子目录
├── 02_专利/  同上
└── 03_论文/  同上
```

## 四条规矩

1. 🔴 **根只做索引，不放内容**：根只写线目录、跨线阶段、下一步依赖、共享权威指针和跨线阻塞；根不写某条线的数字、方法、详细任务状态或执行/复核事实。
2. 🔴 **跨线共享口径住在唯一权威文档**，各线直接指向它，不经过根复制；复述就是漂移入口。
3. **各线自包含**：每条线有自己的完整 `AGENTS.md` / `STATUS.md` / 薄指针、任务卡和收工规则；只进入某条线也能开工。
4. 🔴 **同名文件两层并存是设计**：根和各线都有 `AGENTS.md` / `STATUS.md` / 薄指针时不许合并、去重或互相覆盖。

## 冷启动顺序与自检 scope

- **冷启动顺序**：从根进入时先读根 `AGENTS.md`，按表定位目标线；切换到线目录后只把线级 `AGENTS.md` 当工作入口，再读线级 `STATUS.md` 和任务卡。根索引只用于定位，不替代线级状态。
- **自检 scope**：在线级运行 `python ../scripts/check_handoff.py --scope line`；在根索引运行 `python scripts/check_handoff.py --scope index`。索引型根不应被线级 TL;DR/§3/§4 门误判；线级检查也不应向上读取根入口。

📌 **判据**：一个 agent 只被丢进 `03_论文/`，读完该线 `AGENTS.md` + 它直接指向的权威文档，就能开工——不用读上级、不用翻聊天记录。
